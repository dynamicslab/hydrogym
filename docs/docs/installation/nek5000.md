# NEK5000

[NEK5000](https://nek5000.github.io/NekDoc/) is a spectral-element CFD code developed at Argonne National Laboratory. It solves the incompressible Navier-Stokes equations on unstructured quadrilateral (2-D) and hexahedral (3-D) meshes with high-order polynomial bases. HydroGym's NEK5000 backend provides turbulent channel and airfoil/wing environments (see the environment table of the [README](https://github.com/dynamicslab/hydrogym#available-environments)).

## Option 1: container images (recommended)

The HydroGym images (see [Container images](./containers)) contain the Nek5000 case executables, built for the
HydroGym environments, in `/opt/nek5000/cases/<case>/nek5000` (e.g. `mini_channel` for `TCFmini_3D_Re180`), and
`hydrogym[nek]` in the image's Python environment:

```bash
docker run -it --ipc=host clagemann/hydrogym-cpu:1.0.2          # Nek5000 runs on the CPU in every image
cp -r /opt/hydrogym/examples ~/hydrogym-examples                # /opt is not writable for a non-root user
cd ~/hydrogym-examples/nek/getting_started/1_nekenv_single
./run_nekenv_docker.sh
```

The examples start 1 Python and 10 Nek5000 ranks. Open MPI 5 counts slots by physical core, so on a machine with
10 cores or fewer add `--oversubscribe` to `mpirun` (for the example scripts: `MPIRUN_ARGS=--oversubscribe`).

## Option 2: native build

### System requirements

| Requirement | Notes |
|---|---|
| C compiler | GCC is recommended (`gcc`) |
| Fortran compiler | GFortran is required (`gfortran`) |
| GNU Make | Standard system package |
| MPI | OpenMPI or MPICH — required for all HydroGym runs |
| CMake | Optional, needed only for NekTools |
| X11 libraries | Optional, needed only for the `visnek` visualisation tool |

#### Install system packages (Ubuntu / Debian)

```bash
sudo apt-get update
sudo apt install build-essential       # gcc, make
sudo apt install gfortran              # Fortran compiler
sudo apt install libopenmpi-dev        # MPI
sudo apt install wget                  # makenek downloads the third-party libraries (gslib, ...)
sudo apt install cmake libx11-dev libxt-dev  # optional: NekTools + visnek
```

### Building NEK5000

Clone the repository and add the `bin/` directory to your `PATH`:

```bash
cd ~
git clone https://github.com/Nek5000/Nek5000.git
export PATH=$HOME/Nek5000/bin:$PATH
```

To make the PATH change permanent, add the `export` line to your `~/.bashrc` (or `~/.zshrc`) and start a new shell session.

Build the mesh partitioner and any other tools you need:

```bash
cd ~/Nek5000/tools
./maketools genmap     # mesh partitioner (required)
```

### Verify the build

Download the bundled examples and run a short test case on 2 MPI ranks:

```bash
cd ~
git clone https://github.com/Nek5000/NekExamples.git
cp -r ~/NekExamples/eddy_uv .
cd eddy_uv

genmap                  # partition the mesh: answer eddy_uv, then 0.2 (mesh tolerance)
makenek eddy_uv         # compile the case
nekbmpi eddy_uv 2       # run on 2 MPI ranks (in the background)
tail logfile            # check solver output (ends with "run successful" after ~30 s)
```

A successful run prints residual and timing information for each time step.

### Install the HydroGym Python package

Once NEK5000 is on your `PATH`, install the HydroGym NEK extras:

```bash
pip install hydrogym[nek]
```

This adds `mpi4py`, `omegaconf`, `pymech`, `pettingzoo`, `stable-baselines3`, `supersuit`, and `tensorboard` alongside the core package.

:::note
Git LFS: the Firedrake meshes (`hydrogym/firedrake/envs/*/*.msh`) and the Nek5000 case files (`third_party/nek5000/cases/`) are stored with [Git LFS](https://git-lfs.com). Run `git lfs install` before cloning, or `git lfs pull` in an existing clone; otherwise these files are small pointer files and HydroGym stops with "... is a Git LFS pointer". The wheels on PyPI contain the meshes. The case sources in `third_party/nek5000/cases/` are only in a clone, not in the wheel.
:::

## Running HydroGym with NEK5000

NEK5000 environments use MPMD (Multiple Program Multiple Data) execution: the Python RL controller and the NEK5000 solver are launched as separate MPI programs in the same `mpirun` command, connected via an inter-communicator:

```bash
# in the workspace that prepare_workspace.py creates, e.g. examples/nek/getting_started/1_nekenv_single/ws
mpirun -np 1 python ../test_nek_direct.py --steps 100 : -np 10 nek5000
```

The `: -np 10 nek5000` part starts 10 NEK5000 solver ranks in the same MPI job. Adjust the count to match the mesh partition you compile for your case.

## Loading pre-packaged environments from HuggingFace Hub

HydroGym can download pre-configured NEK5000 case files (mesh, boundary conditions, and environment configuration) from HuggingFace Hub:

```python
from hydrogym.nek import NekEnv

env = NekEnv.from_hf("TCFmini_3D_Re180", nproc=10)
obs, info = env.reset()
```

For offline HPC use, download the environment package on a login node and pass `local_fallback_dir`:

```python
env = NekEnv.from_hf(
    "TCFmini_3D_Re180",
    nproc=10,
    local_fallback_dir="/scratch/<project>/nek_envs",  # holds TCFmini_3D_Re180/
)
```

The same keyword works with `gym.make("hydrogym-nek/TCFmini_3D_Re180-v0", nproc=10, local_fallback_dir=...)`;
`examples/nek/getting_started/gym_make_demo.py` takes it as `--local-dir` (or `LOCAL_DIR`).

## NACA0012 wing (`NACA0012_3D_Re200000_AOA0`)

The case sources are in `third_party/nek5000/cases/naca0012_200k` (built as `/opt/nek5000/cases/naca0012_200k/nek5000`
in the images): NACA0012 at Re_c = 2·10⁵ and zero incidence, span 0.1 c, polynomial order 7.

- **Trip** (`naca_wing.wall`, `tripf.f`): the trip of Wang, Atzori & Vinuesa (J. Fluid Mech. 2025), a wall-normal
  volume force on the line x/c = 0.1 of both sides with 30 spanwise modes, renewed every 0.008 c/U∞, amplitude 10.
- **Time stepping** (`naca_wing.rea`): fixed Δt = 4·10⁻⁵ c/U∞, BDF3/EXT3, RT filter; one action is 31 solver steps
  (`p089`, 1.24·10⁻³ c/U∞).
- **Start** (`naca_wing.restart` = 1): the restart set `rs8naca_wing0.f00005`-`f00008` of the Hugging Face folder
  (`restart_files/init_1`), the developed uncontrolled flow at t = 28 c/U∞ with this trip.
- **Control** (`drl/*.f`): one agent per grid point of the wall faces of the suction-side window 0.25 < x/c < 0.86
  (`register_wall_pts`: every GLL node of each face whose midpoint lies in the window; nodes shared by two faces
  count for each). The
  observation of an agent is [u_t', v_n'] at y+ = 15, the fluctuation about the spanwise mean, divided by the
  friction velocity u_tau(x) of the uncontrolled wing (`X2Utau`, `drl_init.f`). The action a ∈ [-1, 1] is the
  wall-normal velocity a · u_tau,ch with u_tau,ch = 0.0624334733, the friction velocity of the training channel
  (`drl_action.f`); a > 0 blows (velocity into the fluid), a < 0 sucks; zero net mass flux holds on every spanwise
  line (`p090` > 0).
- **Resources.** The mesh has 220,528 elements, at most 54 per rank (`SIZE`: `lelt = 54`), so the case needs at least
  4084 MPI ranks. `prepare_workspace.py --env NACA0012_3D_Re200000_AOA0 --profile NEK5000_v17`
  fetches the restart set (8 × 21 GB plus a 3.6 GB mask, about 175 GB) and copies it into the workspace: plan for about
  490 GB and pass `--cache-dir` to keep the cache out of `$HOME`. On a single workstation use the NekRS port
  (`examples/nekrs/wing`).

`NekEnv` copies the case files of `compile_path` (`nek5000`, `naca_wing.re2`, `.map`, `.wall`, `.restart`,
`forparam.i`, `stat_pts.in`) into the run folder. The values of `environment_config.yaml` belong in the `.rea`
(viscosity → `p002`, `dt` → `p012`, `ndrl` → `p089`, `znmf_avg` → `p090`, `target_cfl` → `p026`, `frame` → `p092` (`wall`, the default: wall-tangent frame),
the `power` section → `p096`, ...). Nek5000 reads the `.rea` once when it is launched, so
`examples/nek/getting_started/prepare_workspace.py --profile NEK5000_v17` writes them into the `.rea` of the workspace
before the launch (`--config FILE` for a configuration other than the environment's; pass the same file to `NekEnv`).
`NekEnv` warns when the `.rea` of the run folder differs from its configuration. The pretrained wing policies of `policies/naca0012_wing_re2e5/` run with the NekRS port of this case
(`examples/nekrs/wing`, see [NekRS](./nekrs)).

## NEK5000 version note

HydroGym is tested against the master branch of [Nek5000/Nek5000](https://github.com/Nek5000/Nek5000). The master branch is recommended over release tarballs because using `git clone` makes it straightforward to pull in bug fixes:

```bash
cd ~/Nek5000
git pull origin master
```
